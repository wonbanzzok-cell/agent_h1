# 이미지 저장 규칙 (v1)

이 규칙은 AI 도구(예: Higgsfield MCP, `mcp__higgsfield__*`)로 이미지를 만들어 이 프로젝트에 저장할 때마다 적용된다.

## 0. 이 규칙이 필요한 이유

- Higgsfield MCP는 원격 서버라서 이 컴퓨터에 파일을 쓸 수 없다. 만든 이미지는 Higgsfield 클라우드에 남고, URL로 돌아온다.
- 결과마다 `rawUrl`(원본 파일, 예: 2048×2048 PNG)과 `minUrl`(작은 WebP 미리보기)이 있다. `rawUrl`은 로그인 없이 내려받을 수 있다.
- 따라서 이미지는 프로젝트에 자동으로 저장되지 않는다. 아래 절차에 따라 직접 내려받는다.
- 생성 도구의 `folder_id` 옵션은 Higgsfield 안의 폴더를 정하는 것이지, 이 컴퓨터의 폴더를 정하는 것이 아니다.

## 1. 생성 전: 비용 확인

- 먼저 `get_cost: true`로 생성 도구를 호출한다. 실제로 생성하지 않고 크레딧 비용만 알려 준다.
- 비용과 현재 잔액(`balance`)을 사용자에게 보고하고, 사용자가 승인한 뒤에만 생성한다.
- 사용자가 명시적으로 요청하지 않으면 `use_unlim`이나 `use_free_gens`를 설정하지 않는다.

## 2. 저장 위치

| 용도 | 폴더 |
|------|------|
| 블로그 글에 쓸 이미지 | `blog/<topic>-<YYYY-MM-DD>/images/` (그 글의 폴더) |
| 그 밖의 모든 용도 (슬라이드, 보고서, 일반) | `images/<topic>-<YYYY-MM-DD>/` |

- `<YYYY-MM-DD>`에는 생성한 날짜를, `<topic>`에는 짧은 영어 케밥 케이스 이름을 쓴다.
- 폴더는 첫 이미지를 저장할 때 만든다.

## 3. 파일 이름

- 각 파일 이름은 `<topic>-<NN>.<ext>`로 한다(예: `camping-gear-01.png`).
- `<NN>`은 두 자리 번호다. 폴더에 이미 있는 가장 큰 번호 다음부터 이어 붙인다.
- 확장자는 원본 파일의 것을 그대로 쓴다(예: `.png`, `.jpg`, `.webp`).

## 4. 내려받는 방법

- `minUrl`이 아니라 `rawUrl`을 내려받는다. 생성 결과, `jobs_wait`, `show_generations`에서 얻는다.
- `curl`을 쓴다. 예: `curl -sSfL -o "<경로>" "<rawUrl>"`.
- 내려받은 뒤 파일이 있는지, 크기가 0이 아닌지, 이미지 형식인지(예: `file` 명령이나 `Content-Type` 확인) 검사한다.

## 5. 생성 기록: `metadata.json`

- 이미지를 저장한 폴더마다 `metadata.json`을 둔다. 이미지 하나당 항목 하나를 추가하고, 기존 항목은 지우지 않는다.
- 각 항목에는 다음을 기록한다:

```json
{
  "file": "camping-gear-01.png",
  "tool": "higgsfield",
  "model": "z_image",
  "prompt": "...",
  "job_id": "5f756190-...",
  "raw_url": "https://...",
  "credits": 1.0,
  "created_at": "2026-10-26"
}
```

- 번역본이 필요 없도록 Markdown이 아니라 JSON으로 둔다.
- 블로그 폴더 구조에서는 `metadata.json`을 이미지와 함께 `images/` 안에 둔다.

## 6. 안전

- 기존 파일을 덮어쓰지 않는다. 이름이 이미 있으면 다음 번호를 쓴다.
- 파일 삭제는 사용자가 동의할 때만 한다.
- 이 규칙은 CLAUDE.md의 작업 절차보다 우선하지 않는다. 생성하거나 저장하기 전에 할 일 목록을 보고하고 승인을 받는다.
