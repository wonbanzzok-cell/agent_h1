# 브라우저 제어 규칙 (v1)

이 규칙은 이 프로젝트에서 웹 브라우저를 제어하는 모든 작업에 적용된다. 페이지 열기, 클릭, 입력, 폼 작성, 스크린샷 촬영, 실제 브라우저가 있어야 읽을 수 있는 페이지 읽기가 여기에 포함된다.

## 0. 범위와 도구

- 브라우저 제어에는 Playwright MCP 도구(`mcp__playwright__*`)를 쓴다.
- 처음 호출하기 전에 ToolSearch로 도구 스키마를 불러온다(예: `select:mcp__playwright__browser_navigate,mcp__playwright__browser_snapshot`).

## 1. 트리거 키워드: 묻지 않고 Playwright 사용

사용자 요청에 다음 표현이나 같은 뜻의 표현이 있으면, 어떤 도구를 쓸지 묻지 않고 Playwright MCP로 작업한다.

- "브라우저를 열어서 작업" / "브라우저 열어" / "브라우저로"
- "웹 제어" / "웹을 제어해"
- "직접 작업" / "직접 들어가서" / "직접 해줘"
- "사이트에 접속해서"
- 같은 뜻의 영어 표현(예: "open the browser", "control the web", "do it directly in the browser")

## 2. 트리거 키워드가 없을 때: 먼저 묻기

요청에 트리거 키워드가 없더라도 Playwright MCP로 작업할 수 있거나 더 잘할 수 있다면, 바로 호출하지 않는다. 먼저 "Playwright로 브라우저를 열어 작업해도 될까요?"처럼 사용자에게 묻고, 사용자가 동의한 뒤에만 호출한다.

- 대표적인 경우: 로그인이 필요한 페이지, JavaScript로 화면을 그리는 페이지, 스크린샷이 필요한 작업, 블로그 에디터 작업(예: `blog/`의 네이버 블로그 원고).
- 동의는 그 동의를 받은 작업에만 적용된다. 새 작업에서는 다시 묻는다.
- 단순한 정보 조회는 WebSearch나 WebFetch로 충분하면 그것을 우선 쓰고, Playwright 사용 여부는 묻지 않는다.

## 3. 우선순위와 안전

- 이 규칙은 CLAUDE.md의 작업 절차보다 우선하지 않는다. 트리거 키워드는 어떤 도구를 쓸지만 정한다. 실행 전에 할 일 목록을 보고하고 승인을 받는 절차는 그대로 지킨다.
- 되돌리기 어렵거나 다른 사람에게 보이는 동작(결제, 게시글 발행, 메시지 전송, 계정 설정 변경)은 실행하기 직전에 사용자에게 다시 확인한다.
- 비밀번호 같은 로그인 정보는 직접 입력하지 않는다. 사용자에게 브라우저에서 직접 입력해 달라고 요청한다.
- 작업이 끝나면 `mcp__playwright__browser_close`로 브라우저를 닫는다.
